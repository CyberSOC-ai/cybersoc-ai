## Context

CyberSOC AI needs comparable SLM, retrieval, fine-tuning, inference and agent experiments across five students. Metadata, metrics, artifact references and versioned agent trajectories must remain reproducible. [Conventions](../../experiments/README.md) and [research rationale](../../experiments/RESEARCH.md) define the portable record independently of a vendor.

## Options considered

| Criterion | MLflow | Langfuse | Weights & Biases |
|---|---|---|---|
| Documented capabilities | Classical experiment runs and GenAI traces | LLM tracing/evaluation/prompt workflows | Experiment collaboration and artifact versioning; Weave for GenAI |
| Documented hosting path | Local server with SQLite; shared hosting configurable | Web/worker, Postgres, ClickHouse, Redis/Valkey, blob storage | Managed academic offering; eligibility and plan conditions require verification |
| Project fit | One candidate covering classical benchmarks and later tracing | Attractive for focused LLM observability; more services in documented self-hosted architecture | Attractive when team prefers a managed service |
| Unverified here | Runtime integration, overhead, resource use, export/reload, shared-server security | Same; deployment operations | Account eligibility, quotas, data-sharing/privacy settings, export/reload |

Sources checked 2026-10-15: [MLflow hosting](https://mlflow.org/docs/latest/self-hosting/), [MLflow tracing FAQ](https://mlflow.org/docs/latest/genai/tracing/faq/), [Langfuse hosting](https://langfuse.com/self-hosting), [W&B academic offering](https://site.wandb.ai/research/). This is a documentation comparison, not measured performance or cost ranking.

## Proposed decision

Use MLflow as the experiment-tracking tool, subject to review of this ADR. Keep Git as authority for code/config/docs and project record conventions. Keep data/model artifact storage selection in ADR-006. MLflow stores tracking metadata, metrics and references; retain portable sanitized JSON records and artifact manifests outside the UI.

Start with a local exploratory deployment when implementation begins. Pin a tested MLflow release then; do not claim an untested version has passed. A shared deployment must document authentication/access, protected storage, backup/restore, retention and export before exposure. Do not expose an unauthenticated tracker or send sensitive SOC content to external services by default. Tool selection does not authorize account creation, deployment or sensitive-data upload.

## Consequences

- One tool can cover model benchmarking and later agent tracing; no second tracker is required by this task.
- Project experiment/run/trace IDs remain distinct from MLflow IDs and have an explicit mapping. Metrics logging does not itself create traces.
- Tool deployment and integration cost remain real work; no measured simplicity, resource or latency claim is made.
- S5-T03 validates a small LangGraph trace, failures, sanitization, export/reload and run-to-trace mapping. S1-T02 can initially produce portable records without blocking on a hosted server.
- Reconsider if team hosting, operational capacity, access control or integration evidence makes MLflow unsuitable. Record a superseding ADR instead of silently changing historical results.

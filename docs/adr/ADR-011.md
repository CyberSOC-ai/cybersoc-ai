# ADR-011: Retire legacy data/RAG and rebuild from the shared release

- Status: Approved by Ahmed for local implementation; no PR/team review claimed
- Date: 2026-11-13
- Decision owner: Ahmed

## Context

The earlier pilot datasets, preparation bundles and RAG implementation had
different paths/defaults from the agreed frozen shared-dev-v1 release. Ahmed
requested removing them and rebuilding RAG incrementally from a clean foundation.

## Decision

Retire the old data loaders/CLI, RAG ingestion/retrieval/generation code, adapter,
prepared corpora/indexes and implementation-specific tests/configuration. Preserve
shared-v1 and its incident-only No-RAG workflow, local models/runtime, backend
foundations, v1 contracts, independent metric checks and historical evidence.

The API recognizes `vector_rag` but returns 503 before invoking any runner;
there is no fallback. The old `vector_runner` injection argument is removed.
Existing v1 schema mode values remain unchanged for future implementation.

Use explicit release IDs and pinned manifests. Stage changes separately, validate
and agree the next snapshot, then activate a new release without changing earlier
bytes. Keep evaluator judgments and future held-out groups separate. Derived
artifacts must record source/configuration/model identities.

## Consequences and evidence

RAG is unavailable until rebuilt and validated. Removing its old tests reduces
coverage; passing retained tests does not validate a replacement implementation.
No requirement for Vector/Graph/Hybrid, evaluation or later roadmap work is waived.

The [cleanup record](../data/cleanup-reset.md) documents exact boundaries,
preservation, local checks and limitations. The [data workflow](../data/workflow.md)
defines future releases. Historical implementation notes remain dated evidence,
superseded as active instructions. Google Drive remains the selected artifact
store under [ADR-006](ADR-006.md); no remote changes were made by this reset.

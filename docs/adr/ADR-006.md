# ADR-006: Artifact/model storage

- Status: Selected by project owner for B0; team review and full handoff acceptance pending
- Date: 2026-11-11
- Decision owner: Ahmed (@ElrhAhmed)
- CDC reference: §23

## Context

The team needs versioned artifacts that can be fetched from local and cloud
environments without relying on one computer. CDC §8 separates GitHub source and
configuration from larger data, model, index and experiment artifacts. B0 requires
one selected shared store and an independently reproducible persistence cycle.

## Options considered

Google Drive and S3-compatible object storage were considered as storage options.
Ahmed selected Google Drive as the team's available shared service. No cost,
throughput, capacity or comparative reliability benchmark was performed.

## Decision

Use Google Drive for B0 shared artifacts. The initial frozen source release is
`shared-dev-v1`, delivered as a ZIP and separate SHA-256 file in the
[owner-provided release folder](https://drive.google.com/drive/folders/1mHw5ayPQxfuqL26lSgOwTgrK8BtH8bl1).
Keep code/configuration and release identity in GitHub. Keep source releases,
model artifacts, derived indexes/graph exports and run bundles separate.

Preserve releases without overwriting their bytes. New source content receives a
new release ID and manifest. Every derived artifact/run references its source
release and configuration identities. Secrets do not belong in the artifact store.

## Consequences

- Teammates can obtain the same source package using the documented file IDs and
  hashes; cloud access/setup and fresh reproduction still need verification.
- Drive filenames and links do not guarantee immutable contents. Verify downloads
  against the Git-tracked ZIP/manifest hashes and record new versions explicitly.
- Prefer anyone-with-link Viewer access for frozen releases, with edits limited
  to maintainers. On 11 November 2026, the folder metadata showed link-based Writer
  access. That remains a configuration gap, not a verified immutable hosting setup.
- The package includes source-specific usage limitations. Hosting does not resolve
  the outstanding redistribution questions or turn draft criteria into gold labels.
- Revisit the provider if artifact size, automated access, capacity or retention
  needs outgrow the chosen arrangement. No storage quota or service guarantee is assumed.

## Evidence and approval

The [release guide](../data/shared-dev-v1.md) records contents, exact hashes,
download/verification steps, access observations and remaining work. Local package
checks passed; Drive contains the ZIP/checksum, and the uploaded checksum matches
the expected local ZIP hash. A teammate/cloud reproduction is not yet evidenced.

Selection was confirmed by Ahmed in the project discussion. No team-reviewed PR,
hosted CI result or B0 completion is claimed by this record. The previous placeholder
decision is superseded by this concrete selection; later changes require a new
decision record or an explicit superseding update.
